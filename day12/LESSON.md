# Day 12 상세 학습 - 함수를 값처럼 선택하기

## 학습 목표

함수 포인터 선언과 호출을 익히고 콜백, 함수 테이블, `void *` 기반 범용 인터페이스의 장단점을 이해합니다.

## 1. 함수 포인터

함수도 코드가 위치한 주소를 가집니다. 함수 포인터 형식에는 반환형과 모든 매개변수 형식이 포함됩니다.

```c
typedef int (*BinaryOperation)(int, int);
BinaryOperation operation = add;
int result = operation(3, 4);
```

`typedef`가 없으면 괄호 위치가 복잡하므로 별칭으로 의도를 표현합니다. 형식이 다른 함수를 억지로 저장해 호출하면 안 됩니다.

## 2. 함수 테이블과 콜백

메뉴 번호에 대응하는 함수 포인터 배열을 만들면 긴 `switch` 대신 데이터 중심으로 연산을 선택할 수 있습니다. 배열 인덱스를 사용하기 전에 반드시 범위를 검사하세요.

콜백은 어떤 작업이 일어날 때 호출할 함수를 다른 함수에 전달하는 패턴입니다. 정렬 비교, 배열 변환, 이벤트 처리 등에 사용됩니다.

## 3. void 포인터

`void *`는 임의 객체의 주소를 담을 수 있지만 가리키는 자료형 정보가 없어 직접 역참조할 수 없습니다. 실제 형식을 알고 있는 코드에서 올바른 포인터로 변환해야 합니다.

```c
const int *number = data;  /* data가 실제 int를 가리킨다는 계약 */
```

잘못된 형식으로 해석하면 크기, 정렬, 표현이 맞지 않습니다. 범용성의 대가로 컴파일러의 자료형 검사가 약해지므로 인터페이스 문서가 중요합니다.

## 완료 기준

함수 포인터 형식을 읽고 쓰며, 호출할 함수가 실행 중 선택되는 이유와 `void *`가 실제 형식 정보를 보존하지 않는다는 점을 설명하면 완료입니다.
