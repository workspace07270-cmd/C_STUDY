# Day 15 상세 학습 - 전처리와 여러 파일로 나누기

## 학습 목표

전처리 지시문의 역할을 이해하고 헤더와 구현 파일을 분리해 재사용 가능한 모듈을 구성합니다.

## 1. 전처리 단계

전처리기는 실제 C 컴파일 전에 `#include`, `#define`, 조건부 컴파일을 처리합니다. `#include`는 헤더의 내용을 가져오고 매크로는 토큰을 치환합니다. 자료형을 이해하는 함수 호출과 달리 단순 치환에는 예상치 못한 부작용이 있습니다.

```c
#define SQUARE(x) ((x) * (x))
```

괄호는 우선순위 문제를 줄이지만 `SQUARE(i++)`는 인수를 두 번 평가합니다. 같은 기능을 `static inline` 함수로 구현하면 자료형 검사와 한 번 평가를 보장할 수 있습니다.

## 2. 헤더와 구현 분리

헤더 `.h`에는 외부에서 사용할 자료형, 상수, 함수 선언을 둡니다. `.c`에는 함수 정의와 외부에 숨길 `static` 구현을 둡니다. 사용하는 쪽은 헤더만 포함합니다.

```c
#ifndef CALCULATOR_H
#define CALCULATOR_H
int add(int a, int b);
#endif
```

include guard는 같은 헤더가 여러 경로로 포함되어도 중복 선언 문제를 막습니다.

## 3. 컴파일과 링크

여러 소스는 함께 컴파일할 수 있습니다.

```powershell
gcc -std=c17 -Wall -Wextra main.c calculator.c -o calculator.exe
```

선언은 있지만 정의를 링크하지 않으면 undefined reference 같은 링크 오류가 발생합니다. 반대로 같은 외부 함수를 여러 파일에 정의하면 중복 정의 오류가 납니다.

## 4. 조건부 컴파일

`#ifdef DEBUG`는 디버그 빌드에만 진단 코드를 넣을 때 유용합니다. 조건부 코드도 각 구성에서 실제 컴파일해 보지 않으면 한쪽 경로의 오류를 놓칠 수 있습니다.

## 완료 기준

전처리 오류·컴파일 오류·링크 오류를 구분하고 작은 프로그램을 헤더 1개와 소스 2개로 분리해 빌드할 수 있으면 완료입니다.
