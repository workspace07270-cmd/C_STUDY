# Day 16 상세 학습 - 열거형으로 상태 표현하기

## 학습 목표

의미 없는 정수 대신 이름 있는 열거값을 사용하고 `switch`와 상태 전이 함수로 제한된 상태를 모델링합니다.

## 1. 열거형의 목적

```c
typedef enum {
    STATUS_READY,
    STATUS_RUNNING,
    STATUS_DONE
} Status;
```

`0`, `1`, `2`만 사용하는 코드보다 각 값의 의미가 분명하고 디버깅하기 쉽습니다. 값을 명시하지 않으면 첫 원소는 0이고 이후 1씩 증가합니다. 프로토콜처럼 정확한 숫자가 중요하면 직접 값을 지정합니다.

## 2. 문자열 변환

열거값은 출력 시 정수이므로 사람이 읽을 이름으로 바꾸는 함수가 유용합니다. `switch`가 모든 알려진 값을 처리하더라도 외부 데이터나 강제 변환으로 범위 밖 값이 들어올 수 있어 `default` 또는 함수 끝의 방어 처리를 둡니다.

## 3. 상태 전이

상태 머신은 현재 상태와 사건에 따라 다음 상태를 결정합니다. 예를 들어 결제 전 주문이 배송 완료로 바로 이동하면 안 됩니다. `change_status(current, requested)`에서 허용 규칙을 검사하면 상태 변경 코드가 여러 곳에 흩어지는 것을 막습니다.

## 4. 주의점

C의 열거형은 다른 언어의 강한 제한형과 달리 런타임의 모든 잘못된 정수를 막지 못합니다. 열거형 변수를 반복문의 정수처럼 무리하게 증감하기보다 다음 상태를 반환하는 함수를 두는 편이 모델을 명확히 합니다.

## 따라 하기와 완료 기준
