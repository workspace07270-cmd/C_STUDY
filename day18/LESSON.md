# Day 18 상세 학습 - 텍스트 파일의 생명주기

## 학습 목표

파일을 열고 읽거나 쓴 뒤 닫는 전체 과정을 구현하며 EOF, 오류, 상대 경로, 텍스트 형식을 이해합니다.

## 1. FILE 포인터와 모드

`fopen`은 성공 시 파일 스트림 포인터, 실패 시 `NULL`을 반환합니다. `"r"`은 기존 파일 읽기, `"w"`는 새로 쓰며 기존 내용을 지우고, `"a"`는 끝에 추가합니다. 작업 전 모드의 데이터 손실 가능성을 확인하세요.

```c
FILE *file = fopen("notes.txt", "r");
if (file == NULL) {
    perror("notes.txt");
    return 1;
}
```

상대 경로는 소스 파일 위치가 아니라 프로그램을 실행한 현재 작업 폴더를 기준으로 해석됩니다.

## 2. 읽기 반복

`while (!feof(file))`은 잘못된 대표 패턴입니다. EOF 표시는 읽기를 시도해 실패한 후에 설정되므로 이전 데이터를 한 번 더 처리할 수 있습니다. 실제 읽기 함수의 성공 여부를 조건으로 사용합니다.

```c
while (fgets(line, sizeof line, file) != NULL) {
    fputs(line, stdout);
}
```

반복 후 `ferror(file)`이 참이면 정상 EOF가 아닌 입출력 오류입니다.

## 3. 쓰기와 닫기

`fprintf`, `fputs`도 실패할 수 있습니다. 중요한 파일은 반환값과 `fclose` 결과를 확인하세요. 버퍼에 남은 데이터가 실제 장치에 기록되는 과정에서 닫기 오류가 발견될 수 있습니다.

## 4. 텍스트 형식 설계

사람이 읽고 수정하기 쉽지만 구분 문자가 데이터에 포함되거나 지역별 숫자 표현이 달라질 수 있습니다. CSV를 직접 처리할 때 따옴표와 쉼표 규칙이 복잡하므로 단순 분리만으로 모든 CSV를 처리할 수 없음을 기억하세요.

## 완료 기준

파일 없음, 권한 문제, 빈 파일, 마지막 개행 없음, 매우 긴 한 줄을 테스트하고 EOF와 읽기 오류를 구분할 수 있으면 완료입니다.
