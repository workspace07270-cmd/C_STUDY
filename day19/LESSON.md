# Day 19 상세 학습 - 이진 데이터와 파일 형식

## 학습 목표

`fread`·`fwrite`로 고정 크기 항목을 처리하고 구조체 원시 저장 방식의 호환성 한계를 이해해 파일 형식을 설계합니다.

## 1. 이진 모드와 항목 수

```c
size_t written = fwrite(records, sizeof records[0], count, file);
```

반환값은 바이트 수가 아니라 완전히 처리한 항목 수입니다. 기대한 `count`와 비교해야 합니다. Windows에서는 이진 파일에 `"rb"`, `"wb"` 모드를 사용해 텍스트 개행 변환을 막습니다.

## 2. 구조체를 그대로 저장할 때

학습 예제처럼 동일 프로그램에서 잠시 저장하고 읽는 것은 간단하지만 영구·교환 형식으로는 문제가 있습니다. 컴파일러 패딩, CPU 바이트 순서, `int`와 `double` 표현 및 크기 차이 때문에 다른 환경에서 읽지 못할 수 있습니다. 포인터 멤버를 저장하면 주소 숫자만 기록되어 다시 실행했을 때 의미가 없습니다.

## 3. 파일 헤더와 버전

견고한 형식은 파일 종류를 확인할 매직 바이트, 형식 버전, 레코드 수를 먼저 기록합니다. 읽을 때 크기와 범위를 검증한 뒤 메모리를 할당해야 악성 또는 손상 파일로 인한 과도한 할당을 막을 수 있습니다.

## 4. 직렬화 전략

정수는 고정 너비 자료형과 정해진 바이트 순서로 필드별 저장하고 문자열은 길이와 바이트를 저장합니다. 부동소수점은 호환 정책을 별도로 정해야 합니다. 쓰기 중 실패 시 기존 파일을 손상시키지 않도록 임시 파일에 완성한 뒤 교체하는 방식도 고려합니다.

## 따라 하기

파일을 일부러 중간에서 잘라 읽기 실패가 감지되는지 확인하세요. 레코드 수를 실제보다 크게 바꾼 파일도 거부해야 합니다.

## 완료 기준

텍스트와 이진 형식의 장단점, 구조체 raw 저장이 이식 불가능한 이유, 버전 필드가 필요한 이유를 설명하면 완료입니다.
